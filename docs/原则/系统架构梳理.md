# 系统架构梳理（minidrama · 短剧生产管理工具）

> 梳理时间：2026-10-13（2026-10-13 晚 增补移动端远程访问）
> 定位：**本地运行的短剧生产管理工具**（Electron 客户端 + 本地 SQLite），并且**桌面电脑自身可充当服务器**，供手机扫码远程控制。
> 本文档属**开发原则侧**的技术架构；业务规则见 `docs/业务规则/`。

---

## 一、系统定位

一个**在用户本地电脑运行的桌面工具**，把「Agent 调度短剧生成」的完整工作流产品化：

- 管理自己的剧本（CRUD + 版本）
- 把剧本变成**分镜**，分镜做**版本管理**
- 挨个生成（生成方式：调远程 API / 调本地 ComfyUI）
- 管理产物（抽帧预览、码率体检、产物清单）

**两种使用形态，同一套功能：**
1. **桌面形态**：Electron 窗口直接操作（本地）。
2. **手机远程形态**：桌面电脑运行后「启用手机访问」→ 弹出**二维码** → 手机扫码在浏览器打开**网页版** → 功能与桌面端**完全一致**，可远程控制这台电脑干活。

⛔ 不是「部署一个独立服务器网站」——**服务器就是运行 Electron 的那台电脑自己**（主进程内嵌 HTTP 服务）。无独立后端服务进程、无数据库服务进程（SQLite 单文件直连）。

---

## 二、技术选型（用户拍板 2026-10-13，晚 增补移动端）

| 层 | 选型 | 说明 |
|----|------|------|
| 桌面框架 | **Electron** | 主进程跑 Node.js（后端+内嵌服务），BrowserWindow 承载桌面 UI |
| 本地数据库 | **SQLite** | 单文件，主进程直连（推荐 `better-sqlite3`） |
| **前端（单一代码库）** | **React / Vue + Tailwind CSS（响应式）** | 同一份前端同时跑在：① Electron BrowserWindow（桌面）② 任意浏览器（手机远程）。**保证功能 100% 一致** |
| 内嵌 HTTP 服务 | **Express / Fastify（主进程内）** | 监听 `0.0.0.0:<port>`，托管前端静态文件 + 提供 REST API |
| 实时通道 | **WebSocket（ws / socket.io）** | 生成进度 + ComfyUI 实时日志推送到桌面与手机（落实「黑窗口=进度可见」） |
| 二维码 | `qrcode` npm 库 | 「启用手机访问」时生成，编码可访问 URL |
| 远程可达（可选） | 路由器端口映射 / 隧道（cloudflared·ngrok·frp） | 手机不在同 WiFi 时，把本地服务暴露到公网 URL |
| 打包 | **electron-builder** | Windows → NSIS `.exe`；macOS → `.dmg` / `.app` |
| 生成调度 | 主进程内调度器 | 调本地 ComfyUI（端口 8189）或远程生成 API |

### 为什么这样选（本地工具 + 自托管服务器 + 单一前端）
- 用户要「本地电脑运行的工具」：打包成 EXE 即用，不部署服务器。
- **桌面电脑自己当服务器**：主进程内嵌 HTTP 服务，手机扫码即可控，无需额外机器。
- **单一响应式前端**：桌面窗口和手机网页是同一份代码，避免维护两套 UI、保证功能一致；iOS/Android 都走浏览器，天然通吃（对应你说的「网站可以被安卓访问，也可以被 iOS 访问」）。
- Electron 主进程有完整 Node 能力：spawn/管理 ComfyUI、读内存、ffmpeg 抽帧——这些是纯前端做不到的，所以重活在主进程，前端只发指令、收进度。

## 三、移动端访问（用户 2026-10-13 晚 补充，现已支持）

**结论：移动端通过「Electron 电脑自托管 Web 服务 + 扫码」实现，Android / iOS 浏览器均可访问，功能与桌面端一致。原生 App 不是必须。**

### 两种实现路径（用户提的两种）
| 路径 | 做法 | 评价 |
|------|------|------|
| **A. 原生 Client（RN / Flutter / 原生）** | 为安卓/iOS 各写一套 App，调同一后端 API | 体验最原生，但**要维护两套代码**，且与桌面 UI 易分裂 |
| **B. 网页版（推荐，你描述的兜底方案）** | Electron 主进程内嵌 HTTP 服务，托管同一份响应式前端；手机浏览器打开即同功能 | **一份代码、双端通吃、功能 100% 一致**，落地最快 |

**采用路径 B 为主**：Electron 启动后「启用手机访问」→ 内嵌服务监听 `0.0.0.0:<port>` → 生成二维码（编码访问 URL）→ 手机扫码开网页 → 远程控制。原生 App（路径 A）作为未来可选项，非 v1 必需。

### 手机访问流程
```
桌面 Electron 运行中
  ↓ 用户点「启用手机访问」
主进程：启动内嵌 HTTP 服务（0.0.0.0:<port>），托管前端 + REST/WS
  ↓ 计算可访问 URL（见第四节网络）
生成二维码（qrcode）→ 显示在桌面窗口
  ↓ 手机扫码（同 WiFi 用 LAN IP；远程用隧道 URL）
手机浏览器打开网页版 → 与桌面端同一功能：管理剧本/分镜/生成/看进度/看产物
  ↓ 所有操作经 REST/WS 打到主进程 → 主进程调 ComfyUI/API 真正干活
```

### 安全（桌面变服务器必须考虑）
- 手机访问**默认关闭**，需用户主动「启用」。
- 启用时生成**一次性访问令牌 / PIN**，手机首次打开须校验，避免局域网/公网裸奔。
- 监听 `0.0.0.0` 仅在启用手机访问期间；关闭即退回仅本地。

## 四、模块划分

```
minidrama-tool（Electron 应用）
├─ main/                        # 主进程 (Node.js) = 后端 + 内嵌服务器
│   ├─ db.ts                   # SQLite 连接与迁移（better-sqlite3）
│   ├─ comfyManager.ts         # ComfyUI 启停/探活/每3段重启/队列
│   ├─ generator.ts            # 生成调度器（API 或本地 ComfyUI）
│   ├─ ffmpeg.ts               # 抽帧/码率体检
│   ├─ server.ts               # ★内嵌 HTTP 服务（Express/Fastify）：托管前端 + REST API
│   ├─ ws.ts                   # ★WebSocket：生成进度 + ComfyUI 实时日志
│   ├─ mobileAccess.ts         # ★启用手机访问：起服务 + 算URL + 生成二维码 + 令牌
│   ├─ tunnel.ts               # 可选：远程可达（cloudflared/ngrok/frp 客户端封装）
│   └─ ipc.ts                  # 桌面 BrowserWindow ←→ 主进程 通信
├─ web/                        # ★单一响应式前端（React/Vue + Tailwind）
│   ├─ 剧本管理                 # CRUD + 版本（桌面与手机共用）
│   ├─ 分镜编辑器              # 剧本→分镜，分镜版本管理
│   ├─ 生成面板               # 选方式(API/ComfyUI)+进度条+实时日志
│   └─ 产物库                 # 抽帧预览/码率体检/产物清单
└─ assets/ + database.db       # 本地 SQLite 文件（随工具走）
```

- **主进程**做重活（进程管理、文件、DB、ffmpeg、ComfyUI 调度、内嵌服务）——落实业务原则里的「显卡不许空转 / 黑窗口=进度可见 / 长任务坑」。
- **前端（web/）是单一代码库**：同时被 Electron BrowserWindow（桌面）和 HTTP 服务（手机）加载，**功能完全一致**。
- 桌面窗口与手机网页都通过 **REST + WebSocket** 与主进程通信，无功能差异。

## 五、网络与可达性（手机怎么连上这台电脑）

| 场景 | 访问 URL | 怎么来 | 二维码编码 |
|------|---------|--------|-----------|
| **同 WiFi（本地）** | `http://<桌面LAN IP>:<port>` | 主进程读本机局域网 IP（如 `192.168.x.x`） | 直接编码 LAN IP |
| **跨网络（远程）** | `https://<公网域名>:<tls>` | 路由器端口映射（公网 IP）**或** 隧道（cloudflared/ngrok/frp） | 编码公网 URL |

- 用户原话：「只要这台电脑打通了外网连接，手机端就可以连接这台电脑」。
  - 同 WiFi：电脑有局域网 IP 即可，无需外网。
  - 远程（手机在 4G/5G）：电脑需**对外可达**——要么路由器做端口映射 + 公网 IP，要么跑隧道把本地服务暴露到公网 HTTPS。**隧道最省心**（免路由器配置），v1 建议内置一个隧道客户端封装（如 cloudflared）。
- ⛔ 公网暴露必须配令牌/PIN（见第三节安全），且建议用隧道自带的 HTTPS，不要明文裸端口。

## 六、数据模型（SQLite 核心表）

| 表 | 作用 |
|----|------|
| `scripts` | 剧本（标题、内容、状态、定版标记） |
| `storyboards` | 分镜（归属剧本、镜头序列、提示词） |
| `storyboard_versions` | 分镜版本（同一分镜的多版，支持版本管理/回滚） |
| `shots` | 镜头（单镜站位/机位/参考图/提示词，落实七条铁律的空间连续性） |
| `generations` | 生成任务（方式 API/ComfyUI、状态、进度、日志、来源桌面/手机） |
| `products` | 产物（路径、大小、时长、码率、体检结果） |
| `mobile_access` | 手机访问会话（令牌/PIN、过期、来源 IP） |

> 详细 schema 在开发阶段由架构原则「公共函数注册制 / 收敛」约束，避免散落建表。

## 七、生成流程（API 或本地 ComfyUI，桌面/手机同入口）

```
用户在桌面或手机网页点「生成」（同一前端、同一 REST/WS）
  ↓
主进程生成面板选方式：
  ├─ 本地 ComfyUI  → comfyManager 探活 8189 → generator 提交队列（每3段重启）
  └─ 远程 API      → 走 V2RAYN 代理(127.0.0.1:10808)，密钥走环境变量
  ↓
WebSocket 实时推送：进度条 + ComfyUI 日志（桌面窗口与手机网页同步可见，落实「黑窗口=进度可见」）
  ↓
出片 → ffmpeg 抽帧 + 码率体检 + 产物清单（落实产物与交付原则）
```

- 续写链：奇数段 fixed，之后连续两段 chain 接上一段，每 3 段断链重启（详见 `docs/业务规则/生成引擎原则.md`）。
- 队列常备 backlog，GPU 占用 ≈ 100%（落实「显卡不许空转」）。

## 八、与两条柱子的关系

- **开发原则（`docs/原则/` + `AgentWorkPrinciples`）**：本架构的测试/架构收敛/CI/CD/分支/统一日志/掉坑笔记由此约束。
- **业务原则（`docs/业务规则/`）**：本架构的「显卡不许空转 / 黑窗口进度可见 / 产物清单 / 工具会骗人 / V2RAYN 死代理 / 十阶段七铁律」由业务原则约束，本架构负责把它们**落实**成代码与界面。
- **手机远程访问**是业务原则「黑窗口=进度可见 / 显卡不许空转」的自然延伸：手机网页同样实时看进度、远程提交生成任务占住 GPU。
