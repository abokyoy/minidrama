# 生产调度原则（业务级）

> 领域：短剧生产系统的**运行纪律**。属业务原则，项目级、非用户级、非开发规则。
> 这些规则约束「系统如何调度生产」，与 `docs/原则/`（怎么写代码）平级并行。

---

## 1. 显卡不许空转（最高原则，优先级最高）

> 用户原话：「给你一个原则 你记录到最高原则中去 最高效利用显卡 确保显卡一直在跑任务 查找问题的话 这个片有问题在找问题 就同时生成下一个片 要合理调度显卡资源 确保显卡一直有任务在做」

1. **显卡任何时候都必须有任务在跑。** 生成是 20–30 分钟的机器时间，GPU 空转 = 白烧电 + 白等。
2. **发现问题绝不暂停流水线。** 这一片有问题 → **照样提交这一片**（占住 GPU），同时并行：① 查根因并改提示词 ② 把**下一片**也提交进队列。
3. **队列要常备 backlog。** 一次至少排 2 段，跑完一段立刻补一段；断链/kill/重启的那几十秒用「提前提交下一片」填上。
4. ⛔ **禁止**「跑一片 → 等 → 查 → 改 → 再跑下一片」这种串行——那是把 20–30 分钟机器时间全变成等待。
5. ⛔ 两 ComfyUI 实例不能同时跑（抢显存会崩）；但**提交进队列**不占显存，可以提前排。

---

## 2. 说人话（最高原则，优先级高于其它表达习惯）

1. 结论先行：先回答「目的能不能达到 / 问题能不能解决」。
2. 给「让我做什么」最详细、最易懂、最好操作的步骤（点哪里、填什么）。
3. 多个方案时一句话说清每个方案的优缺点，让用户自己选，不替他决定。
4. ⛔ 禁止大篇幅高密度术语堆砌；已知技术细节可内部用，但给用户看的正文必须白话化。

---

## 3. 命令必带 timeout + 后台（工程执行纪律，业务侧）

1. 每个命令/生成任务都必须带 `timeout`；超过正常耗时 2 倍立刻诊断原因（网络/死循环/内存）。
2. 长任务（生成视频、批量渲染）一律**后台运行 + 立刻回报进度**，不在主流程里空等/轮询。
3. 等结果用「等通知」，不用 sleep 轮询（轮询本身不产出东西）。

---

## 4. 报错不原地停（业务侧）

```
① 捕获错误栈 ② 归因（逻辑 bug / 命令写法 / 环境损坏）
③ 环境问题先修，修不好就绕过（换执行方式、换工具、脚本落盘+读文件代替终端回显）
④ 记入掉坑笔记
```
⛔ 同一命令入口连续两次失败，禁止第三次盲试，必须换路径或换机制。

---

## 5. 队列常备 backlog（与最高原则配套）

- 调度器永远预留下一片可提交任务；本片查问题期间，下一片已在队列。
- 断链重启 ComfyUI（每满 3 段）的间隙用预提交填补，GPU 占用 ≈ 100%。
