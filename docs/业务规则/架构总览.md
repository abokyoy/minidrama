# 业务原则架构总览（短剧生产系统）

> 本文件夹存放**业务原则**——即「这个短剧生产系统」本身的业务规则。
> 业务原则是**项目级**、**非用户级**、**非开发规则**：它描述的是「系统怎么生产短剧」这件事的规则，
> 不是「怎么写好代码」（那是 `docs/原则/` 开发原则的事），也不是跨项目的个人习惯。

---

## 一、业务原则 vs 开发原则（两条平级并行的柱子）

| 柱子 | 位置 | 管的是什么 | 权威来源 |
|------|------|-----------|---------|
| **开发原则（技术铁律内核）** | `docs/原则/` + `AgentWorkPrinciples/` | 怎么把网站/工具写好：测试、架构收敛、CI/CD、分支、统一日志、掉坑笔记、环境 | `AgentWorkPrinciples`（冲突以其为准） |
| **业务原则（本文件夹）** | `docs/业务规则/` | 这个系统「生产短剧」的业务规则：GPU 调度、生成引擎、产物交付、网络、剧本方法论 | 本文件夹（项目自身沉淀） |

⛔ 两条柱子**平级并行，没有谁高于谁**。开发原则管「工程怎么做」，业务原则管「业务怎么跑」。

---

## 二、业务原则领域划分

业务原则按领域拆成以下子文件，每个文件管一类规则：

| 子文件 | 领域 | 核心内容 |
|--------|------|---------|
| `生产调度原则.md` | 生产运行纪律 | 显卡不许空转（最高原则）/ 说人话 / 命令必带 timeout+后台 / 报错不原地停 / 队列常备 backlog |
| `生成引擎原则.md` | 视频生成引擎 | 长任务特殊坑（内存/重启/显存）/ 黑窗口（进度可见）/ 调用方式（API 或本地 ComfyUI）/ 续写链 |
| `产物与交付原则.md` | 产物与交付 | 产物清单（时间/名/大小/路径）/ 工具会骗人（校验器自验·抽帧人眼·花屏查码率）/ 真实路径核对 |
| `网络与环境原则.md` | 网络与环境 | V2RAYN 死代理 / localhost 不代理 / 外网走代理 |
| `创作方法论原则.md` | 短剧内容方法论 | 十阶段流水线 / 七条铁律 / 定版存档 / 风格锚点（权威细节在 skill `short-drama-creation`） |

---

## 三、业务原则的维护纪律

- 每条业务规则必须是**可被执行、可被验证**的（带「⛔禁用」「必须」「实测」等硬约束），不许写空话。
- 任何一次踩坑（生成异常、显存冲突、效果翻车）若暴露了新业务规则，**必须当场写入对应子文件**，并同步记一笔到 `docs/掉坑笔记/`（开发原则侧）。
- 业务规则与开发原则冲突时：**业务规则描述「系统该做什么」，开发原则描述「代码该怎么写」**，二者维度不同，冲突极少；真冲突时提请用户裁定。
- 业务规则随项目演进持续补充；跨项目通用的业务坑可回灌到 `AgentWorkPrinciples`（由用户拍板）。

---

## 四、与系统架构的关系

- 本文件夹 = **业务规则**（"做什么、按什么规矩做"）。
- `docs/原则/系统架构梳理.md` = **技术架构**（"用什么技术、模块怎么分、数据怎么存"），属开发原则侧。
- 两者配合：业务原则定义约束，技术架构落实约束（例如「黑窗口=进度可见」在架构里落实为「应用内进度视图 + ComfyUI 实时日志」）。
- **扩展能力（已确认）**：手机远程访问 = 桌面电脑自托管 Web 服务 + 二维码，手机浏览器功能与桌面端一致；详见 `docs/原则/系统架构梳理.md` 第三/五节。该能力是业务原则「黑窗口=进度可见 / 显卡不许空转」的延伸（手机也能实时看进度、远程提交生成占 GPU）。
